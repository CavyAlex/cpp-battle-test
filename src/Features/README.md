`Feature` — это директория для реализации игровых фичей. Здесь размещается код юнитов и их поведение, используя возможности, предоставленные `Core`.

## Как добавить юнита

1. **Команда спавна.** Структура в `IO/Commands` по образцу существующих: имя команды и поля, которые придут из сценария.
2. **Класс юнита.** Файлы в `Features/Units`: класс наследуется от `core::Unit`, конструктор принимает команду спавна, проверяет характеристики (`requirePositive`, `requireAtLeast`) и задаёт свойства базового класса. Поведение за ход описывается в `act()` через действия из `Features/Actions`.
3. **Регистрация.** Одна строка в `features::registerUnits` (`Features/Units/Registration.cpp`).
4. **Тесты.** Сценарии в `tests/Features` с ожидаемым логом в комментариях `// EXPECT:`.

Core при этом не меняется.

## Из чего собирать юнита

| Нужно | Как |
|---|---|
| Не ходит | движение `std::nullopt` |
| Ходит быстрее | `core::Movement{.speed = N}` |
| Не занимает клетку | флаг `occupiesCell = false` в конструкторе `Unit` |
| Без HP | HP `std::nullopt` |
| Особые правила, кто и с какой дистанции может его атаковать | переопределить `incomingAttackRange` (`std::nullopt` — атаку не пускает) |
| Удар, выстрел, шаг к цели марша | `meleeAttack`, `rangedAttack`, `marchStep` из `Features/Actions` |
| Урон | `damage` из `Features/Actions` |
| Уйти с поля | `leaveMap()` |

## Правила
- `act()` возвращает `true`, только если юнит что-то сделал: на этом держится условие окончания симуляции.
- Состояние мира меняется только через `World` и действия из `Features/Actions`, тогда каждое изменение попадает в лог. Своё новое событие юнит пишет через `world.log(...)`, а структуру события добавляет в `IO/Events`.
- Указатели на других юнитов не хранятся дольше одного хода: погибших удаляют между ходами. Чтобы помнить юнита, храните его `UnitId`.
- `damage` не принимает юнитов без HP: отбирая цели вручную (например, через `unitsWithin`), пропускайте тех, у кого `getHp()` пуст. `findTargets` делает это сам.
